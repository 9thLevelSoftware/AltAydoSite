<task type="auto">
  <name>Task 1: Add CSP and security headers to next.config.js</name>
  <files>next.config.js</files>
  <action>
Update the `headers()` function in next.config.js to add comprehensive security headers to the `/:all*` source block:

**Replace the existing `/:all*` headers block** with:

```javascript
{
  source: '/:all*',
  headers: [
    {
      key: 'Content-Security-Policy',
      value: [
        "default-src 'self'",
        "script-src 'self' 'unsafe-inline'",
        "style-src 'self' 'unsafe-inline'",
        "img-src 'self' blob: data: https://cdn.fleetyards.net https://images.aydocorp.space https://aydocorp.space https://cdn.discordapp.com",
        "font-src 'self'",
        "connect-src 'self' https://discord.com https://cdn.discordapp.com",
        "object-src 'none'",
        "base-uri 'self'",
        "form-action 'self'",
        "frame-ancestors 'none'",
      ].join('; '),
    },
    { key: 'X-Frame-Options', value: 'DENY' },
    { key: 'X-Content-Type-Options', value: 'nosniff' },
    { key: 'Referrer-Policy', value: 'strict-origin-when-cross-origin' },
    { key: 'Permissions-Policy', value: 'camera=(), microphone=(), geolocation=()' },
    { key: 'X-DNS-Prefetch-Control', value: 'on' },
  ],
},
```

Key decisions:
- `script-src 'unsafe-inline'` is required because Next.js injects inline scripts for hydration. Nonces would be better but force all pages to dynamic rendering. Per the research, this is acceptable for the initial CSP deployment -- nonces can be added later for auth pages specifically.
- `style-src 'unsafe-inline'` is required because Tailwind CSS generates inline styles (Research pitfall 3).
- `frame-ancestors 'none'` replaces `X-Frame-Options: SAMEORIGIN` functionally (CSP takes precedence in modern browsers). Keep X-Frame-Options: DENY for older browser fallback.
- `img-src` includes `https://cdn.discordapp.com` for Discord avatars.
- `connect-src` includes Discord endpoints for OAuth flow.

Keep all existing cache headers blocks (`/_next/static`, `/images`, `/assets`, `/fonts`, `/_next/image`) unchanged.

<task type="auto">
  <name>Task 2: Add security headers to API responses via middleware</name>
  <files>src/middleware.ts</files>
  <action>
Add API-specific cache headers via `next.config.js` headers config. Do NOT modify the middleware matcher -- `next.config.js` `headers()` already applies to all routes including `/api/*` in Next.js 15.

**Concrete action:** Add a new headers block in `next.config.js` targeting API routes specifically for cache control:

```javascript
{
  source: '/api/:path*',
  headers: [
    { key: 'Cache-Control', value: 'no-store' },
    { key: 'Pragma', value: 'no-cache' },
  ],
},
```

Place this block AFTER the `/:all*` block in the headers array. This ensures API responses get the general security headers from `/:all*` (CSP, X-Frame-Options, etc. from Task 1) PLUS the API-specific `Cache-Control: no-store` and `Pragma: no-cache` headers.

**Why next.config.js and not middleware:** The middleware matcher explicitly excludes API routes (`/((?!api|_next/static|...).*)`), and changing it risks breaking the existing auth redirect logic. The `next.config.js` `headers()` function applies unconditionally to all matching routes with no matcher interference -- simpler and safer.

**Verification:** After adding the block, run the dev server and test:
