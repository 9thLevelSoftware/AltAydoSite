<task type="auto">
  <name>Task 1: Create centralized auth-guards.ts module</name>
  <files>src/lib/auth-guards.ts</files>
  <action>
Create `src/lib/auth-guards.ts` with three reusable guard functions following the pattern from 10-RESEARCH.md:

1. `requireAuth()` - Returns `AuthResult` (session, userId, clearanceLevel, role) or `NextResponse` (401). Gets session via `getServerSession(authOptions)`.

2. `requireClearance(minLevel: number)` - Calls `requireAuth()`, then checks `clearanceLevel >= minLevel`. Returns 403 if insufficient.

3. `requireLeadership()` - Calls `requireAuth()`, then checks if role is in `['Director', 'Manager', 'Board Member']` OR `clearanceLevel >= 3`. Returns 403 if neither.

Export the `AuthResult` interface:
```typescript
export interface AuthResult {
  session: UserSession;
  userId: string;
  clearanceLevel: number;
  role: string;
}
```

Import `getServerSession` from `next-auth`, `authOptions` from `@/app/api/auth/auth`, `UserSession` from `@/lib/auth`, and `NextResponse` from `next/server`.

Guard functions return `AuthResult | NextResponse`. Callers use `instanceof NextResponse` check:
```typescript
const auth = await requireLeadership();
if (auth instanceof NextResponse) return auth;
// auth is AuthResult here
```

Add a `RBAC_AUDIT` console.log in `requireLeadership()` when a user is denied: `console.log('RBAC_AUDIT: User ${userId} with clearance ${clearanceLevel} and role ${role} denied leadership access')`. This enables monitoring before enforcement is fully trusted.
