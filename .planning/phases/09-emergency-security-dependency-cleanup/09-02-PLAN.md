1. FIX CALLBACK URL VALIDATION in `src/components/auth/LoginForm.tsx` (SEC-06):

   Add a validation function (can be inline or at module level):
   ```typescript
   function isValidCallbackUrl(url: string | null | undefined): string {
     if (!url) return '/';
     // Must be relative path, no protocol-relative URLs
     if (!url.startsWith('/') || url.startsWith('//')) return '/';
     // Reject URLs with encoded characters that could bypass checks
     try {
       const decoded = decodeURIComponent(url);
       if (decoded.startsWith('//') || decoded.includes('://')) return '/';
     } catch {
       return '/';
     }
     return url;
   }
   ```

   Apply this validation everywhere `callbackUrl` from searchParams is used:
   - Where callbackUrl is read from searchParams (~line 36): validate immediately
   - Where it's passed to `router.replace()`: use validated value
   - Where it's passed to `signIn()` callbackUrl options (both credentials and Discord): use validated value

   The goal: even if an attacker crafts `?callbackUrl=https://evil.com`, the redirect goes to `/` instead.
