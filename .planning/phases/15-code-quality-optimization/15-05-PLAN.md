  For each of these 5 files, apply the following transformation:

  1. Add `import { logger } from '@/lib/logger';` at the top (near other imports)

  2. Replace ALL `console.log(...)` calls with `logger.info(...)`:
     - Extract the message string and any data arguments
     - Convert to structured format: `logger.info('descriptive message', { key: value })`
     - Example: `console.log('STORAGE: [MongoDB] Getting resources')` → `logger.info('Getting resources', { storage: 'MongoDB', collection: 'resources' })`
     - Include relevant context: collection name, operation type, document IDs

  3. Replace ALL `console.warn(...)` calls with `logger.warn(...)`:
     - Same structured format: `logger.warn('warning message', { context })`

  4. Replace ALL `console.error(...)` calls with `logger.error(...)`:
     - The logger.error signature is: `error(message: string, error?: Error, context?: Record<string, any>)`
     - When the console.error has an error object: `console.error('Failed:', error)` → `logger.error('Failed', error instanceof Error ? error : new Error(String(error)), { collection: 'x' })`
     - When console.error has just a string: `console.error('Something bad')` → `logger.error('Something bad', undefined, { collection: 'x' })`

  5. **Pattern for existing log messages:**
     Most storage files use this pattern: `console.log('STORAGE: [MongoDB] <operation> <collection>: <details>')` or `console.log('STORAGE: [Fallback] <operation>')`
     - Extract the operation and details into structured fields
     - Keep the message human-readable but shorter
     - Add `storage: 'MongoDB'` or `storage: 'Fallback'` to context

  Do NOT change any business logic, only logging calls.
