  <action>
  **user-storage.ts:**
  1. Find the function that fetches all users (likely `getAllUsers` or similar).
  2. Add a paginated variant or modify the existing function to accept `{ page?: number, pageSize?: number }` options.
  3. When pagination params are provided:
     ```typescript
     const query = {}; // or existing filter
     const total = await db.collection('users').countDocuments(query);
     const docs = await db.collection('users')
       .find(query, { projection: { passwordHash: 0 } })
       .sort({ aydoHandle: 1 })
       .skip((page - 1) * pageSize)
       .limit(pageSize)
       .toArray();
     return { users: docs, total, page, pageSize };
     ```
  4. When NO pagination params are provided, keep the existing behavior (fetch all) for backward compatibility with other callers.

  **users/route.ts:**
  1. Parse `page` and `pageSize` from URL search params: `const page = parseInt(url.searchParams.get('page') || '1'); const pageSize = parseInt(url.searchParams.get('pageSize') || '25');`
  2. Validate: page >= 1, pageSize between 1-100. Default page=1, pageSize=25.
  3. Call the paginated storage function.
  4. Return JSON with `{ users, total, page, pageSize, totalPages: Math.ceil(total / pageSize) }`.
  5. If the route currently does in-memory slicing, remove that code.

  **planned-mission-storage.ts:**
  1. Find `getAllPlannedMissions` or equivalent function.
  2. Add pagination support: `{ page?: number, pageSize?: number }` options.
  3. When pagination params provided:
     ```typescript
     const total = await db.collection('planned-missions').countDocuments(query);
     const missions = await db.collection('planned-missions')
       .find(query)
       .sort({ scheduledDateTime: 1 })
       .skip((page - 1) * pageSize)
       .limit(pageSize)
       .toArray();
     ```
  4. IMPORTANT: Remove the JS-side sort (research identified lines ~189-193 doing in-memory sort). The `.sort()` in the MongoDB query replaces it. Sort MUST happen before skip/limit.
  5. Return `{ missions, total, page, pageSize }`.
  6. Keep existing non-paginated behavior when params not provided.

  **planned-missions/route.ts:**
  1. Parse `page` and `pageSize` from URL search params (same pattern as users).
  2. Default page=1, pageSize=25.
  3. Call paginated storage function.
  4. Return `{ missions, total, page, pageSize, totalPages }`.
  5. Remove in-memory slicing if present.

  **Important:** Both storage functions must keep the non-paginated path working for any internal callers that expect the full list (e.g., dashboard summary counts).
