<objective>
Implement a MongoDB-backed rate limiter for authentication endpoints, replacing the in-memory rate limiter for auth routes while keeping the in-memory limiter for general API routes.

Purpose: SEC-10 requires persistent, distributed rate limiting on auth endpoints. The current in-memory rate limiter (Map-based) is lost on server restart and per-instance in multi-process deployments, making brute force attacks trivial to circumvent.

Output: `rate-limit-store.ts` with MongoDB-backed atomic rate checking; auth endpoints integrated; TTL index for auto-cleanup.
</objective>

   - Use `findOneAndUpdate` with `$inc: { count: 1 }` and `$setOnInsert: { windowStart, expiresAt }` with `upsert: true, returnDocument: 'after'`

**Login rate limiting (via NextAuth credential provider):**

There is NO separate `/api/auth/login/route.ts`. Login goes through `src/app/api/auth/auth.ts` via the CredentialsProvider `authorize` callback (line 33). The `[...nextauth]/route.ts` catch-all dispatches to it.

Rate-limit login attempts by adding the check inside the `authorize` callback in `src/app/api/auth/auth.ts`:

1. Import `checkRateLimit`, `getRateLimitKey`, `AUTH_RATE_LIMIT` from `@/lib/rate-limit-store`
2. At the top of the `authorize(credentials)` function (before any DB lookup), extract IP from the request context. Since NextAuth's `authorize` callback receives `(credentials, req)` as the second parameter, use `req.headers?.['x-forwarded-for']` or `req.headers?.['x-real-ip']` for IP extraction.
3. Call `checkRateLimit`:
   ```typescript
   const ip = (req?.headers?.['x-forwarded-for'] as string)?.split(',')[0]?.trim() || 'unknown';
   const rateLimitKey = `auth:login:${ip}`;
   try {
     const rateLimit = await checkRateLimit(rateLimitKey, AUTH_RATE_LIMIT.maxRequests, AUTH_RATE_LIMIT.windowMs);
     if (!rateLimit.allowed) {
       throw new Error('Too many login attempts. Please try again later.');
     }
   } catch (e) {
     if (e instanceof Error && e.message.includes('Too many')) throw e;
     console.warn('Rate limit check failed, allowing request:', e);
   }
   ```
4. The `authorize` callback returns `null` for failures and throws for rate limits. NextAuth surfaces the thrown error message to the client.

**Non-login auth endpoints (signup, forgot-password, reset-password):**

These have their own standalone route.ts files with POST handlers. For each, add rate limiting at the top of the POST handler:

1. Import `checkRateLimit`, `getRateLimitKey`, `AUTH_RATE_LIMIT` from `@/lib/rate-limit-store`
2. Extract rate limit key: `const rateLimitKey = getRateLimitKey('auth:signup', request)` (use appropriate prefix per endpoint)
3. Check rate limit:
   ```typescript
   const rateLimit = await checkRateLimit(rateLimitKey, AUTH_RATE_LIMIT.maxRequests, AUTH_RATE_LIMIT.windowMs);
   if (!rateLimit.allowed) {
     return NextResponse.json(
       { error: 'Too many requests. Please try again later.' },
       {
         status: 429,
         headers: {
           'Retry-After': String(Math.ceil((rateLimit.resetAt.getTime() - Date.now()) / 1000)),
           'X-RateLimit-Remaining': '0',
         },
       }
     );
   }
   ```
4. Add rate limit headers to successful responses too:
   ```typescript
   response.headers.set('X-RateLimit-Remaining', String(rateLimit.remaining));
   ```

**Important:** If MongoDB is unavailable (connectToDatabase fails), the rate limit check should fail OPEN (allow the request) with a console.warn, NOT block all auth. Wrap the checkRateLimit call in try/catch with fallback to allow.

Do NOT modify `src/lib/rate-limiter.ts` -- the existing in-memory rate limiter stays for non-auth API routes (like finance). The MongoDB rate limiter is additive, not a replacement.
